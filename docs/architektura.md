- `src/config/GameConfig.ts` — all tunable numbers (player/enemy stats, combat timing) + asset slicing constants. Change balance here, not in entity code.
- `src/core/Assets.ts` — loads the PNGs, builds procedural placeholders for anything missing (so the game always boots even with an empty `/public/assets`), slices the character sheet, extracts the sword/rabbit-face/NPC-portrait sub-textures and each item's icon — a real tile cut from `items.png` for weapons/armor, a colour-swatch placeholder for everything else (or for those same weapons/armor if `items.png` itself is missing).
- `src/core/Animations.ts`, `HitFlash.ts`, `EventBus.ts`, `InputState.ts` — small shared utilities. **`flashHit` takes a `restoreTint` option and it is not cosmetic** — see the enemy-telegraph note in the checklist below.
- `src/core/Interactables.ts` — **the one place that answers "what is the player standing next to".** Types only, no state: an `Interactable` carries a `kind` (`npc` / `campfire` / `gather`), a `key`, its own range and its position. `GameScene` keeps a single list and runs a single per-frame pass where **the nearest in-range one wins**, announcing changes through one `EVENT.interactableNearby`; `Merchant` and `Campfire` implement it, and every UI gates on the kind it cares about.
  - **This replaced a per-kind proximity loop, a per-kind event and a per-kind `keydown-E` binding.** Nothing stopped an NPC and a campfire being in range at once except *map geometry* — the fire is placed further from the Hunter than their two interact ranges combined, measured by hand and asserted in Python (`CAMPFIRE.spawnSearchRadii`). That guarantee is **pairwise**: every new kind must be re-measured against every existing one, on every map, and the failure is silent ("E does nothing" / "E does two things"). Herb gathering — dozens of hand-placed nodes per map — is what made it untenable.
  - **Deliberately NOT an `interact()` method.** The three kinds are answered in three different places and should stay there (a paused conversation window, a one-shot prompt, an instant pickup); one method would drag UI decisions into entity code. This answers "may I?", exactly like `Abilities` against `GameScene`.
  - Verified in-engine: sweeping 140 tiles of the forest's NE corner gives 7 tiles with only the NPC prompt, 6 with only the fire prompt, **0 with both** — and the widget states match the geometric counts exactly. Then, forcing the case the old code could not resolve (campfire moved to 40px from the Hunter, so both are always in range): nearer-Hunter → NPC prompt only, nearer-fire → fire prompt only, exact tie → registration order wins, **always exactly one prompt**. Cooking still works end to end through the new path (6 raw → 5 raw + 1 cooked at the fire; the same tap far away does nothing).
  - The old distance rule survives as a **placement preference** — a prompt that swaps as you shuffle between two things is still bad — but it is no longer what makes the key unambiguous.
  - ⚠ **`GameScene.removeInteractable` must NOT clear `nearby` before re-running the pass.** The change is announced by comparing the new winner against `nearby`, so clearing it first makes "nothing here now" compare equal to "nothing here before" — no event fires and the prompt stays on screen **forever**, until the player happens to walk into something else. Found in-engine, not by reading: gathering worked, the item arrived, and the bar just sat there over bare grass. Leaving the removed object in place for one comparison is also what correctly *keeps* the prompt up when another plant of the same species is still in range.
- `src/core/Gathering.ts` + `src/world/NodeSpawner.ts` + `src/entities/Gatherable.ts` + `src/ui/GatherPrompt.ts` — **herb gathering**: the first thing in this game the player can do to the world that isn't hitting it or talking to it. See the checklist entry below.
- `src/core/Protection.ts` — **the one place damage reduction is computed, for BOTH directions of combat.** Plain pure functions over data (`armorPointsAgainst` / `reductionFromPoints` / `mitigate`), not a class or a service, and deliberately NOT a second damage resolver — the resolvers stay exactly where they were (`GameScene.damageMatchingEnemies` player→enemy, `Player.takeDamage` enemy→player).
  - **It exists because the project briefly had TWO unrelated shapes of protection.** The player ran defence POINTS through `d/(d+K)` with a cap; an enemy (for one iteration) carried a raw percentage per damage type. Two shapes means quality, durability and every future modifier need two implementations and drift apart. **Points won**, because everything that will ever modify protection — workmanship (`instanceDefense`), a future armour-durability multiplier, a buff — naturally scales a point TOTAL, while scaling a percentage has no single correct answer ("+20% on 60%" is either 72% or 80pp).
  - ⚠ **`damageType` is optional everywhere and its absence means "no type involved", returning the points unchanged.** That is what let the player's armour keep working untouched while enemies still have no damage types of their own: `Player.takeDamage(amount, damageType?)` already accepts one and nothing passes it yet. Verified — the untyped reduction is byte-identical to before (full leather 35.1%, full steel 53.3%).
  - **No armour = full damage.** There is deliberately no "unarmoured resistance" anywhere in the model, and `mitigate` never rounds below 1.
- `src/ui/WorldPrompt.ts` — the bottom-centre "press E to…" bar, shared by `CampfirePrompt` and `GatherPrompt`. Extracted when gathering became its third user: the position (`width/2, height − 70`) was already written out three times, and three copies of a screen coordinate is how two prompts end up 6px apart after somebody nudges one. `NpcDialog` still keeps its own — its prompt is entangled with the panel's lifecycle.
- `src/core/Progression.ts` — XP/levels/attributes singleton (melee damage range reads the equipped weapon via `Equipment`, falling back to `PLAYER.damageMin/Max`). `src/core/Inventory.ts` — 16-slot backpack + gold singleton (stacking, buy/sell/use). `src/core/Equipment.ts` — 10 equip slots (weapon/offhand/head/chest/gloves/legs/boots/amulet + two rings — `EQUIP_SLOTS` is the one list, never hand-copy it), a thin layer over `Inventory` (equip/unequip just move an item across that boundary); exposes `weaponDamage`, the attack-variant plumbing (`weaponAttacks`/`activeAttack`/`setActiveAttack`, see the checklist entry below) and `defenseAgainst(type?)`/`reductionAgainst(type?)` (diminishing-returns armor mitigation, now per damage type — `defenseReduction` is the untyped case and is unchanged in value). It also **owns the `DamageType` and `AttackVariant` types**, next to `MeleeShape`, because all three describe how a blow is delivered. `src/core/Quests.ts` — quest-log singleton (`available`/`active`/`completed` per quest from `GameConfig.QUESTS`); collect-objective progress is read LIVE from `Inventory` (not stored), so selling the items lowers it and turn-in consumes them + grants the reward. `src/core/Items.ts` — item id/type helpers over `GameConfig.ITEMS`. `src/core/Skills.ts` — learnable-abilities singleton (one-off unlocks bought with skill points at a trainer NPC, from `GameConfig.SKILLS`); `skinning` gates boar-hide loot. `src/core/Save.ts` — **four save slots** (`SlotId`: one `"auto"` + three manual), each its own `localStorage` key. The autosave writes on every Progression/Inventory/Equipment/Quests/Skills/Dialogue change exactly as the single save always did; manual slots write only when the player asks. `TitleScene` and the PlayerPanel "ZAPIS" tab are the only things that call `load()`/`clear()`. Bump `SAVE_VERSION` when the save shape changes — a mismatched save is discarded (fresh run), never migrated. `src/core/Session.ts` — the playtime clock the slot cards are read from, ticked in `GameScene.update()` so paused menus don't count.
- `src/entities/Enemy.ts` — **config-driven base** enemy (patrol/chase/contact-damage/knockback/death/HP bar, all from an `EnemyConfig`) with protected hooks (`updateChase`, `canDeaggro`, `onLoseAggro`, `onGainAggro`, `updateAnimation`, `postMove`, `onHurt`, `onDeathVisual`) and a public `aggro()` so one creature can wake another. `onHurt`/`onDeathVisual` are one-shot hooks fired from `takeDamage`/`die` for a subclass with a real sheet to play a hurt/death clip — added for Wolf, default no-op, reusable by the next creature. **`postMove` fires right after patrol/chase has written the frame's velocity, to SHAPE it** — added for the rabbit's hop, whose gate has to apply to wandering and chasing alike while `patrol` stays private. It sits **inside** the knockback guard (an impulse owns the body outright, so there is no AI velocity to shape) and **before** `updateMotionFx`, which is the whole reason it isn't done in `updateAnimation`: the lean/stretch would otherwise still be computed from the ungated glide it exists to replace. A new enemy is a config block + subclass + map spawns, not a forked AI. The six:
  - `Rabbit.ts` — base + RABBIT config, plus **hop locomotion and the sploch** (see the checklist entry below), and the `updateAnimation` override that plays its real idle/walk/run sheet (see rabbit.png below).
  - `Boar.ts` — telegraphed charge (approach→telegraph→lunge→recover); also has a real idle/walk/run sheet via the same `updateAnimation` hook (see boar.png below).
  - `Wolf.ts` — **pack AI**: orbit at `pack.circleRadius` → dart in → peel off, plus a **howl** that pulls every wolf-kin within `pack.callRadius`. Also the base class for the Szary. Has a real 4-direction idle/walk/growl/bite/hurt/death sheet (wolf.png) — see boar.png/rabbit.png below — gated to `kind === "wolf"` so the Szary, who inherits from Wolf but has no directional sheet of his own yet, never touches it.
  - `GreyWolf.ts` — **Szary**, the named elite from the prologue: bite-and-backstep duel + an enrage phase under 40% HP. Has his own directional sheet (greywolf.png — bigger, paler, heavier-browed, scarred; NOT wolf.png at a larger scale) via the same `Wolf.updateAnimation`/`onHurt`/`onDeathVisual`/`playOneShot` machinery, pointed at his own texture through `this.animFn`.
  - `Spider.ts` — the ranged/support enemy: holds a firing band, retreats out of melee, spits a slowing web.
  - `VenomSpider.ts` — **Skoczek jadowity**, the melee spider: telegraphed bite that plants a stacking venom, re-tested for range at the moment of impact. The one creature whose threat grows over the course of a fight rather than being constant.
- `src/entities/Projectile.ts` — enemy shots (currently only the web) + the `ProjectileHost` interface `GameScene` implements. Entities fire through that interface rather than importing GameScene, which would be a cycle.
- `src/entities/Player.ts` — self-contained player (movement, combat, death). `src/entities/Merchant.ts` — stationary NPC (static portrait frame, immovable body). `src/entities/Loot.ts` — ground item drops (bob idle, lifetime despawn, no movement).
- `src/scenes/BootScene.ts` (load + placeholder setup) → `TitleScene.ts` ("Kontynuuj"/"Nowa gra", see Save.ts above) → `GameScene.ts` (gameplay) + `UIScene.ts` (HUD/controls, runs in parallel as an overlay).
- `src/ui/VirtualJoystick.ts`, `AttackButton.ts`, `HUD.ts` — touch controls + HUD, communicate with gameplay only via `InputState`/`Controls`/`GameEvents` (no direct scene reach-through). `src/ui/PlayerPanel.ts` (character sheet + backpack + quest log + minimap + save slots, as five tabs on one frame — `C`/`B`/`L`/`M`/`Z` open straight to a tab, switch tabs, or close) follows the same pattern. **NPC interaction is a dialogue hub**: `src/ui/NpcDialog.ts` owns the whole conversation (proximity, the `E` key, the prompt, and the game pause) and hands off to exactly one focused view at a time — `ShopPanel.ts` (buy/sell), `QuestPanel.ts` (accept/turn-in) or `TrainerPanel.ts` (learn skills). Those three deliberately **do not pause/resume on their own** — the pause belongs to the conversation, or stepping from the shop into the trainer would briefly unpause the world. Keys: `E` ends the conversation from any layer, `ESC` steps back one level (view → dialogue → closed). All panels extend `src/ui/PanelBase.ts` (shared chrome: container, background, close button, tooltip, `makeButton()`, centre-on-screen, pause-while-open); shared text styling/colours live in `src/core/theme.ts` (`UI` palette + `textStyle()`), and one-shot combat/loot FX (floating numbers, expanding rings) in `src/core/Fx.ts`.
- `src/world/TiledMap.ts` — loads maps authored in **Tiled** (JSON export). This is the primary map path; read the header comment before touching it (required export settings + why collision is flattened by hand).
- `src/world/MapBuilder.ts` — the original code-authored map (`GROUND` array + `OBJECTS` list). Now the **fallback**, used only when the Tiled JSON or Teren.png is unavailable, so the game always boots. Its four tile picks point into two regenerated sheets, so cross-check them against `docs/kafle.json` after any `build_tilesets.py --od-zera`; there is no bridge art any more and that entry deliberately draws a colour block.
